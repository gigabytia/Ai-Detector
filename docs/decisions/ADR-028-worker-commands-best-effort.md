# ADR-028. Команды worker'у — уведомление, а не транзакция

Статус: принято (Milestone 3). Развивает [ADR-004](ADR-004-event-bus.md).

Желаемое состояние камеры (`enabled`, источник) сначала фиксируется в PostgreSQL, затем API публикует `camera.changed` / `camera.restart` в `ad:worker:commands`. Если Redis недоступен, ошибка публикации пишется в лог, а запрос оператора всё равно успешен: состояние уже сохранено.

Worker не теряет изменения: после каждой (пере)подписки на канал он делает полную сверку по `GET /api/v1/internal/worker/cameras`; если API недоступен при обработке команды, сверка повторяется. Команда — только сигнал «перечитай камеру», её содержимое не меняет состояние.

Фактическое состояние (`runtime`) API берёт из `ad:camera:{id}:status` (TTL 5 с). Ключа нет → `runtime: null`; UI показывает «Нет обработчика» для включённой камеры и «Остановлена» для выключенной.

**Почему:** pub/sub не гарантирует доставку; сверка по источнику истины делает систему самовосстанавливающейся без очередей с подтверждением.
