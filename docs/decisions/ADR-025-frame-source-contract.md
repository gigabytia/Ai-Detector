# ADR-025. Контракт FrameSource и обработка ошибок источника

Статус: принято (Milestone 3)

`FrameSource` — блокирующий интерфейс, используется только из потока захвата своей камеры:

| Метод | Смысл |
|---|---|
| `start()` | открыть источник |
| `read()` | ждать следующий кадр; `None` — была запрошена остановка |
| `stop()` | потокобезопасно разблокировать `read()`; ничего не освобождает |
| `close()` | освободить ресурсы (OpenCV `VideoCapture`); вызывается только из потока захвата |

Разделение `stop`/`close` нужно потому, что `cv2.VideoCapture` нельзя безопасно освобождать из другого потока во время `read()`.

Ошибки делятся на два типа:

* `SourceUnavailableError` — временная (сеть, камера перезагружается, поток оборвался) → `RECONNECTING`, повтор с экспоненциальной задержкой 1 → 30 с (`RECONNECT_*`); после первого удачного кадра счётчик сбрасывается.
* `SourceFatalError` — источник не заработает без изменения настроек (файл не найден, не декодируется, неизвестный сценарий) → `ERROR` без повторов. Выйти из `ERROR` можно перезапуском или изменением источника; `CameraManager` при `camera.changed` пересоздаёт сессию в `ERROR`.

Непредвиденное исключение в потоке захвата логируется со стеком и тоже даёт `ERROR` только этой камере (§37).

RTSP-ошибка подключения считается временной: по ней нельзя отличить неверный адрес от выключенной камеры.

**Почему:** оператор видит «Камера недоступна / повторное подключение» для сетевых проблем и «Ошибка» для того, что само не пройдёт.
