# ADR-004. Шина событий

Статус: принято (Milestone 1)

Redis выполняет две роли. Pub/sub — для мгновенной доставки (`ad:events:live`, `ad:events:updates`, `ad:cameras:status`, `ad:worker:commands`). Redis Streams (`ad:ingest`, consumer group `api-ingest`) — для надёжной записи событий, треков и аналитики: ingest-задача в каждом процессе API читает пакеты и пишет их в PostgreSQL, сообщение удаляется только после записи. Команды worker'у — уведомления, а желаемое состояние лежит в БД; после разрыва связи worker делает полную сверку. Kafka не используется (§158).

**Почему:** Одна инфраструктура вместо двух; consumer group даёт ровно одного получателя при N процессах API; при недоступном PostgreSQL данные не теряются.
