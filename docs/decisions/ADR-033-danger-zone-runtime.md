# ADR-033. Danger zone: геометрия, время и граница этапа

Статус: принято (Milestone 6)

## Хранение и координаты

Зона — простой polygon из 3–64 различных вершин в координатах исходного кадра 0..1, замыкается неявно. Pydantic отклоняет нулевую площадь, повторяющиеся вершины, самопересечения, самокасания и наложение соседних рёбер. Обход допускается в обоих направлениях; граница считается внутри. Проверяется нижняя центральная точка bbox (anchor), а не center.

API и engine поддерживают до 16 зон на камеру (ограничение нагрузки для MVP); UI редактирует первую зону по времени создания, явно предупреждая о других, и не меняет их (ADR-009). CRUD блокирует строку родительской камеры, чтобы сериализовать добавление зон и soft-delete. Геометрию проверяет приложение; PostgreSQL дополнительно проверяет тип JSONB и число вершин.

Редактор рисует SVG поверх canvas в общей системе координат JPEG, `preserveAspectRatio="xMidYMid meet"`. Это интерактивный overlay, не изображение, вшитое в кадр. Клики переводятся через contain-scale и offsets; чёрные поля игнорируются. Нормализованные координаты сохраняются независимо от разрешения. Есть клавиатурный ввод координат, undo, clear, cancel, включение/отключение и подтверждение удаления. Черновик не записывается автоматически и не меняет целевой ID при обновлении списка.

## Правила и жизненный цикл

`SceneRegistry` владеет отдельным `ZoneEngine` на `(camera_id, run_id)` в том же одиночном executor, что ByteTrack. Неизменяемый `CameraSpec` фиксируется при сборе кадра; позднее изменение конфигурации не смешивается с результатом этого кадра. Уведомление Redis + периодическая сверка доставляют изменения конфигурации без переоткрытия источника и сброса track ID.

Для пары трек–зона: OUTSIDE → ENTERING → INSIDE → EXITING → OUTSIDE. Dwell 0.25 с, exit grace 0.5 с, минимум 3 совпадения трека. Пока трек LOST, таймеры заморожены; возвращающий кадр не начисляет пропущенное время. INSIDE/EXITING в любой включённой зоне дают IN_DANGER_ZONE, LOST остаётся LOST. Истёкшие треки удаляют визиты и cooldown. Изменение геометрии/удаление/отключение сбрасывает только затронутые визиты; имя не сбрасывает. Loop, reconnect, source_epoch, разрешение и новый run сбрасывают scene; stop/delete/ERROR/shutdown очищают registry.

Dwell/grace используют source timestamps; cooldown — внедрённый Clock, wall UTC (ADR-010). Cooldown 3 с действует на камеру/run/track/тип, без zone_id (ADR-008). Подавленный вход всё равно завершает ENTERING: отложенного повторного события, пока человек остаётся внутри, нет. Отладочный лог показывает подавление; метрики событий — будущий этап.

## Событие и граница Milestone 6

При подтверждении входа создаётся immutable `DomainEvent` с UUID, camera/run/track/zone, типом PERSON_ENTERED_DANGER_ZONE, severity (по умолчанию critical), occurred_at UTC, source_ts_ms, сообщением и metadata (нормализованные bbox/anchor, dwell, stability). `detector_confidence` — средняя confidence совпадений за окно ENTERING; `event_confidence = mean × matched_frames / all_processed_window_frames`, включая LOST в знаменателе. Вход один раз за визит; возврат во время EXITING не создаёт второй вход.

События включены в `DetectionResult.events` и структурированный лог активного run. **Это ещё не транспорт и не история событий:** Redis pub/sub + Stream, ingest в PostgreSQL, SSE, телеметрия и панель событий — Milestone 7; снимки — Milestone 8. Не вводим ненадёжный временный ingest или фиктивный список событий. До M7 события при аварии/перезапуске теряются.

Новые настройки вводятся только используемые: API defaults и nullable camera overrides для трёх интервалов (0..3600 с), worker EVENT_MIN_TRACK_HITS и SEVERITY_ZONE_ENTER. Линии и loitering не реализованы.
