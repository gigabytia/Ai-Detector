# ADR-005. Доставка видео

Статус: принято (Milestone 1)

Уровень 1: vision worker сам отдаёт превью по WebSocket `/live/v1/cameras/{id}`. Каждое бинарное сообщение — JSON-телеметрия + JPEG того же обработанного кадра (≤ `PREVIEW_FPS`, ширина ≤ `PREVIEW_MAX_WIDTH`), только пока камера открыта в UI. В браузер путь попадает через тот же origin (Vite proxy в dev, nginx в docker), поэтому frontend знает одну базу URL. Уровень 3: видео через MediaMTX (WebRTC/HLS), WS шлёт только JSON с `frame_id` и `source_ts_ms`, frontend держит буфер телеметрии ~300 мс и рисует ближайшую по времени запись. Допустимое расхождение рамки и кадра на Уровне 3 — до 1 обработанного кадра (≈100 мс при 10 FPS); при сетевой задержке WebRTC больше — рамки скрываются, а не рисуются «мимо». Оба пути — реализации frontend-интерфейса `CameraImageSource`. При нескольких worker'ах прокси должен маршрутизировать по `assigned_worker` — после MVP.

**Почему:** Синхронность кадра и рамок по построению, нет ретрансляции байтов через API, JPEG не кодируется для невидимых камер.
